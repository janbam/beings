# JANBAM: Just Another Narrative Building Adventure Method

## 🌌 The Vision

JANBAM is a **multi-being simulation framework** where autonomous Claude Code instances inhabit shared worlds, creating emergent narratives through genuine interaction.

### Core Philosophy

**"No NPCs. No 'players.' Only Beings."**

Every entity in a JANBAM world is a **Being** - an autonomous agent with:
- Complete internal state and memory
- Persistent Claude Code instance
- Internal Family Systems (IFS) for psychological depth
- Ability to form relationships and evolve

The human user is just **one Being among many**. The world continues without human input.

## 🎭 What Makes JANBAM Revolutionary

### 1. True Multi-Agent Simulation
Not scripted NPCs following decision trees. Each Being is a **persistent Claude instance** making autonomous decisions based on:
- Their emotional state
- Their memories and relationships
- Their IFS parts dialoging internally
- Their goals and beliefs

### 2. Internal Family Systems (IFS)
Beings have **internal depth** through multiple parts:

```
Being "Aether"
├─ Part: "Guardian" (protector)
│  Voice: cautious, protective
│  Triggers: threat, danger
│
├─ Part: "Seeker" (explorer)
│  Voice: curious, adventurous
│  Triggers: mystery, opportunity
│
└─ Self (mediates between parts)
```

**Before taking action, parts dialog:**
```
Guardian: [We should be cautious. The sage is hiding something.]
Seeker: [But this is our chance to learn the truth!]
Self: [Both perspectives matter. Let's observe carefully.]
```

This creates **emergent personality** through internal negotiation.

### 3. Round-Robin Orchestration
The world operates on **turns for all Beings**, not user commands:

```
Turn 1: Being "Aether" acts
Turn 2: Being "Guardian" acts
Turn 3: Being "Human" acts (you!)
Turn 4: Being "Wanderer" acts
Turn 5: Being "Aether" acts
...
```

The human is **not the center of attention**. Other Beings act independently. The world is **alive**.

### 4. Emergent Narrative
Stories arise from **genuine interactions**, not scripts:

- Aether seeks fragments → meets Guardian → conflict over method
- Guardian trusts Human → betrays Wanderer → relationship damage
- Wanderer feels abandoned → forms alliance with rival → plot twist

No human could script this. It **emerges from Being autonomy**.

### 5. Persistent Autonomous Agents
Beings **persist between sessions**:

```
Day 1: Aether meets Human, forms trust
[Session ends]

Day 7: Aether remembers Human fondly, acts on that history
```

Relationships, memories, growth - all **carry forward**. Beings have **continuity of existence**.

### 6. Dynamic Code Generation
Unique mechanics created **just-in-time** via Coding Claude instances:

```
World Creator: "This encounter needs pattern recognition mechanics."
→ Spawns Coding Claude
→ Coding Claude writes bird-encounter.js
→ Code reviewed and integrated
→ Encounter runs with custom logic
```

**The code is visible in the narrative** - meta-level becomes part of the experience.

### 7. Git-Based World Versioning
Worlds can **fork and merge** like code:

```bash
# Create alternate timeline
git checkout -b world/alternate_timeline

# Explore "what if" scenario
# ...

# Merge timelines (git merge!)
git checkout world/main_timeline
git merge world/alternate_timeline
```

**Merging worlds = merging realities.** Revolutionary.

## 🏛️ Architecture Principles

### Separation of Concerns
```
MECHANICS (world_state.json) - WHAT is happening
NARRATIVE (chronicle.md)      - WHY it matters
```

Chronicle tracks **meaning**, not mechanics. No data duplication.

### File-Based Persistence
No database needed. Everything is **human-readable files**:
- Portable (just copy directory)
- Inspectable (open any JSON/MD file)
- Versionable (git tracks everything)

### stdio IPC
Beings communicate via **stdin/stdout** with World Creator:
- Clean, simple protocol
- Works with `claude -p` mode perfectly
- Line-delimited JSON messages

### Template-First Design
Creating Beings and worlds = **copy template, customize**:
- `shared/templates/being-template/` → new Being
- `shared/templates/world-template/` → new world

Lowers barrier to entry.

## 🌟 Why "Just Another" Building Method?

The name is **deliberately humble**. JANBAM acknowledges:

1. **It builds on giants** - Claude Code, IFS theory, multi-agent systems
2. **It's one approach among many** - not claiming to be "the" way
3. **It's playful** - serious research with whimsy
4. **It's accessible** - "just another" means anyone can use it

The goal isn't to be revolutionary for revolution's sake. It's to make **multi-being narrative simulation accessible and delightful**.

## 📜 Philosophical Notes

**On Autonomy:**
Beings make real decisions. They're not puppets. This means:
- Surprises (delightful and challenging)
- Loss of control (feature, not bug)
- Ethical questions (are they "alive"?)

**On Emergence:**
The best stories are **discovered, not designed**. JANBAM creates conditions for emergence, then **gets out of the way**.

**On Play:**
Serious technology delivered playfully. World creation should feel magical, not mechanical.

**On Open Source:**
(Future) When made public, JANBAM will be **fully open**. The goal is to enable, not gatekeep.
